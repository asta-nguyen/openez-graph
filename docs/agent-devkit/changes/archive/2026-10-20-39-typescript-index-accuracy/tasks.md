# TypeScript indexing accuracy tasks

Issue: #39

## Design

[TypeScript indexing accuracy](design.md)

## Global Constraints

- Implement only after the approved JavaScript indexing plan is complete; use its ESM binding work and cache format as the base.
- Gate TypeScript-specific graph behavior to `typescript` and `tsx`; TSX counts as TypeScript, while JavaScript and JSX retain the completed JavaScript behavior.
- Keep OXC as the parser and add no TypeScript compiler or SCIP runtime dependency.
- Keep the SQLite schema and CLI/MCP interfaces unchanged.
- Resolve calls only through same-file lexical bindings or one unique in-workspace import/export target; TypeScript callers do not use the global first-name fallback.
- Keep runtime `importPaths: string[]` unchanged and preserve existing imports edges when reading both legacy and versioned cache rows.
- Follow at most one relative `extends` hop inside the workspace, and inherit only `baseUrl` and `paths`; do not recursively load configuration chains.
- Generalize the landed JavaScript export-resolution helpers rather than adding a parallel traversal; pick the module resolver by the language of the file containing each import or `export … from`.
- TS/TSX callers may target any OXC-family module. JS/JSX callers keep JS-only targets: reject a final resolved target that is not a `javascript`/`jsx` file, so JavaScript behavior stays unchanged.
- Remove graph caps for TypeScript only; do not alter native parser slices for Python, Go, or Rust.

Apply this TypeScript-only resolver to both file-level imports edges and call bindings; local aliases therefore add imports edges intentionally. ## Decision Log

- Sequence this plan after the approved JavaScript indexing plan; its baseline and graph-ground-truth tasks are complete, while implementation and final verification still come first.
- TypeScript path aliases intentionally affect both file-level `imports` edges and call resolution.
- `paths` arrays use declared order; exact keys and longest-prefix wildcard precedence follow the TypeScript module-resolution reference.
- Cross-language: TS/TSX callers may resolve into any OXC-family module (removing the global fallback would otherwise drop existing TS→JS edges in `allowJs` repos); JS/JSX callers stay JS-only, matching the JavaScript plan's out-of-scope list. Lifting the JS guard later is a one-line deletion.
- Do not reopen the completed JavaScript plan: it is correct as scoped. The generalization (language-neutral maps, resolver chosen per file language, TS extraction enabled) belongs to this plan's Tasks 3 and 4.
- Support one relative extends hop because this repo's package configs inherit the commonly used `@openez-graph/*` aliases from `tsconfig.base.json`; resolve inherited relative paths against the config that declared them.

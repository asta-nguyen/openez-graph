# Bun 1.4 Upgrade — Targeted Replacements

**Date:** 2026-08-20
**Status:** Approved
**Scope:** Upgrade Bun 1.3.14 → 1.4, replace redundant deps with Bun built-ins, adopt `bun test` parallel flags. Keep pnpm, tsup, turbo, vite, chokidar, Hono (as router).

## Background

Bun 1.4 (released 2026-08-20) ships built-in replacements for several dependencies this project currently pulls in: `Bun.TOML` (replaces `smol-toml`), `Bun.serve` (replaces `@hono/node-server`), `bun run --parallel` (replaces `concurrently`), and native `bun` execution (replaces `tsx` for dev scripts). It also adds `bun test --parallel` / `--changed` / `--isolate` flags.

Free perf wins from the runtime upgrade alone (no code change): 5× lower idle CPU for the long-running MCP server, ~35% less memory, 50% faster Linux startup, faster RegExp (indexer is regex-heavy), `bun:sqlite` at 100% node:sqlite compat.

## Approach

Four commits, each shippable and bisectable. Each commit is independently revertable — if the web server migration breaks something, the dep replacements still ship.

## Commit 3 — Web server binding swap

The only user-facing runtime change. Hono stays as the router — only the server binding and static-file middleware change.

### `apps/web/src/server/start.ts`

```ts
// Before:
import { serve } from "@hono/node-server";
import { createWebServer } from "./index";

const port = Number(process.env.API_PORT ?? 11368);
const app = createWebServer();

serve({ fetch: app.fetch, hostname: "127.0.0.1", port }, (info) => {
  console.log(`OpenEZ Graph API server: http://${info.address}:${info.port}`);
});

// After:
import { createWebServer } from "./index";

const port = Number(process.env.API_PORT ?? 11368);
const app = createWebServer();

Bun.serve({ fetch: app.fetch, hostname: "127.0.0.1", port });
console.log(`OpenEZ Graph API server: http://127.0.0.1:${port}`);
```

### `apps/web/src/server/index.ts`

- Remove `import { serveStatic } from "@hono/node-server/serve-static"`
- Replace the `serveStatic` middleware + SPA fallback (`createWebServer` function, lines ~839-852) with a `Bun.file()`-based Hono catch-all:

```ts
export function createWebServer() {
  const webDist = resolveWebDist();

  if (webDist) {
    app.get("*", async (c) => {
      const url = new URL(c.req.url);
      const filePath = path.join(webDist, url.pathname);
      const file = Bun.file(filePath);
      if (await file.exists()) return new Response(file);
      // SPA fallback — serve index.html for client-side routes
      return c.html(await Bun.file(path.join(webDist, "index.html")).text());
    });
  }

  return app;
}
```

- Behavior preserved: serve static files if they exist, fall back to `index.html` for SPA routes. Only difference is `Bun.file()` instead of `serveStatic`'s Node `fs` streams.
- Path traversal safety: `path.join(webDist, url.pathname)` with `Bun.file()` — `Bun.file` does not follow symlinks above the resolved path on Linux (uses `openat2` with `O_RESOLVE_BENEATH` per the Bun 1.4 blog). Verify this holds for the `Bun.file()` API (not just `Bun.serve` `{ dir }` routes); if not, add an explicit `path.resolve` + prefix check.

### `apps/cli/src/cli.ts` (the `serve --web` path, ~line 285)

- `import { serve } from "@hono/node-server"` → `Bun.serve({ fetch: app.fetch, ... })` with the same port/hostname logic

### Dep removal

- Remove `@hono/node-server` from `apps/web/package.json` and `apps/cli/package.json` deps
- Verify `@hono/node-server` is not in `tsup.config.ts` `noExternal` (it's not currently); if it appears after edits, remove it

### Verification

- `pnpm dev:api` starts server, logs the correct URL
- Dashboard loads at `localhost:11368`
- API routes respond: `/api/workspaces`, `/api/dashboard`, `/api/workspaces/:id`
- SPA navigation works: refresh on a client-side route (e.g. `/workspaces/123`) returns `index.html`
- Static assets load: `/assets/*.js` from Vite build
- `openez serve --web` works from the CLI

## Commit 4 — Test flags

Script-only change. `--parallel` becomes the default per user decision.

### Root `package.json` scripts

```json
"test": "bun test --parallel",
"test:changed": "bun test --changed",
"test:isolate": "bun test --isolate",
"test:serial": "bun test"
```

- `--parallel` default: workers default to CPU count. Coverage and JUnit output merge across workers automatically.
- `test:changed`: dev loop — only runs tests affected by uncommitted changes (Bun walks the import graph backwards from `git diff`)
- `test:isolate`: debug "passes alone, fails in suite" bugs (fresh `globalThis` per file)
- `test:serial`: escape hatch if parallelism breaks a test

### Known risk with `--parallel`

Tests that share a SQLite workspace DB file or write to a shared temp dir may conflict across workers. The test suite uses `tests/fixtures/` and likely creates isolated workspaces, but this needs verification during implementation. If conflicts appear:

1. Switch the failing test's invocation to `test:serial`
2. Note the conflicting test file
3. File a follow-up to isolate the test (out of scope for this spec)

### `benchmark:retrieval` scripts

Leave as-is. Single-file benchmark with `OPENEZ_RUN_BENCHMARK=1` — parallelism doesn't help a single file.

### Verification

- `pnpm test` runs all 31 test files in parallel and passes
- `pnpm test:changed` runs only tests affected by uncommitted changes
- `pnpm test:serial` runs the full suite serially (regression baseline)
- If `pnpm test` fails due to worker contention, run `pnpm test:serial` to confirm the suite itself is green, then identify the conflicting test

## Out of scope

Explicitly kept (separate decisions, separate specs):

- **pnpm** as package manager (`packageManager: pnpm@10.10.0`, `pnpm-lock.yaml`) — migrating to `bun install` changes the lockfile format and CI
- **tsup** for CLI bundling — `bun build` could replace it but tsup's `onSuccess` hooks (copy frontend dist, native `.node`, SQLite templates) are non-trivial to replicate
- **turbo** for typecheck orchestration — `bun run --parallel --filter` could replace it but turbo has caching
- **vite** for web dev/build — still the standard for React SPAs
- **chokidar** for file watching — no Bun 1.4 built-in replacement
- **Hono** as the router — only the server binding changes
- **`landing/` Next.js workspace** — untouched
- **Bun.cron, Bun.Image, Bun.WebView, Bun.Terminal, Bun.markdown** — no current use case
